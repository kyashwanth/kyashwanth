Prompts for testing

Prompts written for AI coding assistants and LLM-enabled IDEs in agent or chat mode. They tell the assistant what to read in your repo, what to build, which commands to run and how to prove the result. Replace the [PLACEHOLDERS] with your paths and commands.

How to use these in your IDE
  • Point it at real files. Use your IDE's file or folder mentions (for example @src/orders) or paste the paths into the placeholders.
  • Plan first. For anything that edits code, ask for a short plan and approve it before it changes files.
  • Make it prove the work. Every agent prompt ends with a command to run. Keep that step; it turns guesses into evidence.
  • Review the diff. Treat generated tests like a teammate's pull request: check assertions, not just that they pass.
  • Work in small steps and a branch. One prompt, one reviewable change, one commit.
  • Protect secrets. Never put credentials, tokens or customer data in a prompt. This page checks what you type and tells you to revoke or rotate anything that looks like a secret. Values stay in your browser and are never stored or sent anywhere.
  • Save your conventions. Put your test commands and rules in your assistant's project rules file so you do not repeat them (see "Write a testing rules file").
Safety guardrails added to every copied prompt
/

Guardrails: when you copy a prompt, a safety block is added that tells the assistant to stop and warn you if it finds secrets or personal data, to stay on local or test environments, and to ask before risky actions. You can turn it off with the checkbox above. Agent prompts read, edit and run things in your project. Analysis prompts only produce findings or documents and never change your code. Always review what an assistant changes, and never share secrets or customer data.
